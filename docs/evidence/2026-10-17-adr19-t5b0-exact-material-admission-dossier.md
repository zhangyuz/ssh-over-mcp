# ADR 0019 / Issue #259 — T5B-0 exact-material admission dossier

**Prepared:** 2026-10-17. **Decision:** `T5B0_ADMISSION_REFUSED_INCOMPLETE`. **This is source research, not an admission approval, signed policy, independently authenticated material, or an executable instruction.** The two-stage T5B-0 admission -> T5B-1 execution sequence is approved *as process only*; its material/clock/runtime/execution approval remains HOLD under [Issue #259](https://github.com/zhangyuz/ssh-over-mcp/issues/259). This dossier names concrete candidate provenance and the **missing proof needed to resolve one operator decision**. The existing PR #271 `SYNTHETIC_ONLY` Ed25519 proof is not a Sigstore/CMS source-authentication proof.

**Allowed in this slice:** non-executing read-only consultation of public documentation, published registry metadata, and repository source metadata. **Not done/authorized:** download, import, install or execute the candidate Sigstore verifier or its wheels; fetch/bundle trust-root/key bytes as execution inputs; retrieve the actual macOS `.pkg` or `.pkg.sigstore`; privileged/persistent Mac mutation; T5B-1, B0b, UID502/APFS, staging or Linux C. Source URLs and reported digests alone are *not* independently authenticated trust anchors.

### A viable verification sequence, after separate material-collection permission

1. Collect **only explicitly allowlisted candidate metadata/material** in an off-host disposable unprivileged environment. Record independent fetched original-byte hashes, provenance URLs, time and byte count; keep it **untrusted and non-executable**, do not automatically import/install. This step itself needs a distinct operator decision on allowed bytes, host, tool and custody before any acquisition.
2. Obtain first TUF trust root fingerprint and trusted UTC from the separately chosen independent channel. Establish its threshold/rotation chain and rollback floor **before** accepting any cached/latest metadata. If the bootstrap cannot be independently demonstrated, stop and keep everything `CANDIDATE_ONLY`.
3. Review and independently authenticate every policy signer/log/time/root, verifier runtime byte and dependency in A–D, rejecting gaps. Construct a single canonical versioned policy with exact approved numeric limits and consent; no unreviewed fallback to default root, live internet or other CLI.
4. Submit the fixed `A–F` material manifest, evidence citations and **exact proposed command + isolated container/VM image/FD map** for a fresh independent security review and explicit operator T5B-0 admission **and execution** decision. No invocation before that decision.
5. **Only after** admission and a distinct execution consent, demonstrate the exact pinned full-Sigstore signed synthetic GREEN and mandatory RED controls (wrong original bytes/digest, bundle-only declared digest, signer/issuer, Fulcio/log/time/root/expiry, runtime/image, altered evidence). Never turn `SYNTHETIC_ONLY` into actual CPython source authority.

## Decision requested for the *next* security gate, not granted here

**T5B0-COLLECT-CANDIDATES (proposed, not approved):** May a separately designated disposable, no-secrets, non-privileged Linux collection environment fetch **only** the exact public Sigstore **v4.3.0 wheel+its publishing attestation metadata, referenced release metadata and TUF root/targets metadata as untrusted inert bytes** for independent manifest/lineage study? The actual allowed URLs, sizes/digests and immutable custody must be reviewed *before* a download. **Explicit exclusions:** do not import/install/execute Python wheels or verifier; no use of trust roots as authority; no actual Python.org `.pkg` or `.sigstore`; no persistent Mac actions, sudo, UID502, Docker socket, new CI dispatcher or real B0 validation. An approval of candidate collection would **not** approve A–F, T5B-0 execution or T5B-1 acceptance. If the independent OOB root/clock evidence cannot be secured, maintain HOLD and avoid repeated shape-only policy work.

**Current fail-closed answer:** `T5B0_ADMISSION_REFUSED_INCOMPLETE`. Existing B0 `B0_POLICY_CANDIDATE_ONLY`/`B0A_INSPECTED_UNTRUSTED`/`SYNTHETIC_ONLY` are strictly non-authorizing; real B0–B4 / UID502/APFS original-code acceptance remain UNVERIFIED, Linux Slice C deferred.
