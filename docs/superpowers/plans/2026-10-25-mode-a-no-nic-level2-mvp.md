## Acceptance checkpoints — one feature iteration, not a new platform

1. **Offline freeze (current):** document the exact sshd NNP0 → sudo setuid → root-owned fixed launcher → two-cap non-root agent → NNP1/cap-zero workload sequence, per-node separate mount/user manager sidecar with same-node PID mapping, restricted cgroup writer, peer credential socket ACL and node-originated packet-denial rules. Test proposal stays `runtime_execution_authorized=false`. Request independent P1 *design acceptance* before changing Compose.
2. **One test-only execution consent packet (not yet granted):** identify the fresh disposable QEMU/HVF `x86_64` guest image by digest, vCPU/memory/disk limits, `-nic none` / no host shares, approved read-only offline Engine + OCI media manifest, isolated source build/fetch location and canonical domain bounds, ephemeral independent per-node/client keys created **inside guest**, exact privileged OCI settings, node-cgroup delegated paths and the guest trust/cleanup runner. **Explicitly exclude all persistent `yuz.local` Docker, existing Lima guests, host firewall/kernel/cgroup changes, production credentials, Mode B/M2, Ready/merge.** If image/package or manager namespace mapping isn't verifiable, stop before guest or container startup. No separate bespoke ten-`.deb` approval workflow.
3. **Approved build after gate only:** use immutable Ubuntu amd64 platform digest, canonical signed Ubuntu APT and reviewed direct versions, lock final dependencies and minimal trusted launcher/sshd; verify final image hash, userns/cap/NNP and package receipts. Preserve Docker Engine/OCI package bytes and signature/size manifests on reviewed read-only guest media; do not modify trusted Native Level-3 provider.
4. **Trusted guest admission:** independently boot a **fresh** no-NIC/no-share guest from attested read-only media (never the stopped Lima VM), check zero external NICs/routes, exact image/manifest digests, cgroup-v2 and Docker/UID maps. Start only with reviewed manager/sshd OCI spec. Assert `SO_PEERCRED`, PID identity, cgroup subtree ownership and real enforced forwarding hook *before* exposing an SSH listener.
5. **Real A01–A03 Level-2:** demonstrate both node host keys are unique/pinned, genuine MCP→SSH/ForceCommand/manager positives, bad keys/commands/sudo/PTY/forwarding denied, workload NNP=1/cap-zero and cgroup self-migration denied, reversed node→MCP TCP/8000 NEW and node↔node NEW denied with packet counters, host/LAN/Internet unavailable, required Ledger audit-before-effect, restart/teardown and no leftover guest artifacts. Fail on missing proof; no synthetic PASS.
6. **Release gates:** exact-head hosted CI, trusted-main separate Native **Level-3 PASS** (not SKIPPED), full independently signed-off exact-head security review and separate operator Ready/merge consent. Mode B and full typed-FS M2 are independent work, never smuggled into #342.

**Stop conditions:** no trusted builder/guest media; image digest mismatch; any missing capability that prompts unapproved widening; NNP unexpectedly inherited by sudo; root UID namespace maps to persistent host without approved isolation; manager can access ancestors, manager PID mapping is ambiguous or `SO_PEERCRED` mapping fails; leaked socket/FD; unfiltered node→MCP TCP NEW; any unverified guest cleanup. Report `NOT_RUN`/`REFUSED` and preserve nonsecret receipts rather than retrying uncertain privileged actions.
