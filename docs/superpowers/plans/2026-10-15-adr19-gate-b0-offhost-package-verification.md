## Goal, result semantics and scope

Produce an **independently repeatable, non-executing B0 source-verification procedure** for the one candidate `python-3.13.16-macos11.pkg`, using **actual supplied bytes** only after future explicit B0 implementation/artifact-use approval. An initial future **B0a** code slice can prove the artifact digest and independently verified Sigstore bundle on an isolated, credential-free, non-privileged verifier. A distinct **B0b** approval/evidence step is required to assess Apple Installer CMS signing, notarization/revocation policy and *all* package effects. Only an operator-reviewed combination may support an **artifact-source decision**. Neither B0a nor B0b provisions an interpreter, attests installed files, runs UID502, or makes the SOM product macOS-ready.

- In this **docs-only PR**, **no artifact bytes, signature bundles, verifier binaries or package contents are downloaded, read or executed**.
- Future B0 verification must run **off the trusted native orchestrator** in a disposable non-privileged environment. Any Mac-only verification requires a separately approved isolated inspection host, not `Yuz.local`'s persistent E2E runner. Do not bootstrap an untrusted Mac Python to prove itself.
- There is **no automatic authority bit**: B0a output is at most `B0A_EVIDENCE_COLLECTED_UNAPPROVED` and `B0A_REFUSED`; a signed/human approval decision is a separate evidence record, not a caller-provided bool. Gate A statuses and UID502 preflight stay unchanged.

## Threat model and hard refusal rules

Treat the downloaded or fixture package bytes, filename, URL, CMS certificate, Sigstore material, package scripts/BOM, path metadata and evidence files as **untrusted** until validated by independent pinned policy. Refuse:

- Incorrect or absent bytes, hash/version/name mismatch; any mismatch between independently approved digest and full **streamed actual bytes**.
- Same-digest self-reported strings without measured bytes, malformed signatures, wrong cert identity/OIDC issuer or Apple team/purpose, expired/revoked/unverifiable chain, missing offline trust root or valid log inclusion/time, old or forged verification results.
- Symlink/alias/TOCTOU input replacement, re-opened mutable artifact, partially read file or truncated/overlong data. **An FD pins an inode, not its contents**: stable inode, size, mode, timestamps or a before/after hash alone cannot establish non-mutation. **Mandatory in either proposed handoff mode:** import under verified exclusive writer exclusion into a bounded, demonstrably immutable byte snapshot **before** SHA or signature verification; refuse mutable/drifting/unprovably isolated inputs. A future Linux B0a could use a private anonymous `memfd` sealed against write, grow, shrink and seal modification, with seal readback. The hasher must measure the **same verified sealed kernel object** and preserve authenticated snapshot identity in B0a evidence. Until this separately reviewed amendment is operator-approved and merged, the current same-sealed-FD verifier handoff remains binding; if it is unavailable => `B0A_REFUSED`. Under a later **separately approved exact mode/policy**, either (a) the trusted verifier receives **that same sealed descriptor** over authenticated FD inheritance and consumes it without mutable-path reopening, or (b) a pinned verifier checks the Sigstore bundle's **signed message/digest** against `sha256:<locally-computed-sealed-byte-digest>` handed directly from the authenticated hasher. Digest mode **does not mean** the verifier independently read the sealed bytes: acceptance requires a demonstrable, non-circular sealed-bytes → trusted hasher → measured digest → trusted verifier → signed bundle binding proof, with all process/tool/root/identity provenance recorded. Caller-supplied digests, same-source-published checksums, unpinned tool output and any mutable pathname fallback **REFUSE**. Include same-inode concurrent rewrite-and-restore (even with size/mtime preserved), unsealed inputs, substitutions and seal write-attempts as negative tests.
- Parser bombs, oversized XML/JSON/bundle metadata, duplicate/conflicting fields, unsafe compression expansion, traversal/absolute paths, escapes, special files or unknown nested installer payloads. Bound bytes, depth, counts and runtime **before** any recursive evaluation, sorting, or comparison on arbitrary attacker objects.
- Package installation scripts with unreviewed shell/network, application-launch, privilege escalation, global symlink/PATH changes, package receipt changes, update hooks, uncontrolled writes or postinstall behavior. **Listing** scripts is not approving them. A package with incomplete or uninspectable operations remains refused.
- Unsafe verifier acquisition or unpinned dependencies; hidden network calls; any `curl | sh`, `pip install` on the target Mac, `installer` invocation, chmod/chown, root/UID502 invocation, dynamic execution of package scripts, provider/runner changes, or running the candidate Python itself.

A package's authentic signature does **not** imply a safe system-wide installation. Package signing, content/effects approval, installed provenance and point-of-use loader closure are four distinct proofs.

## Mandatory B0a ↔ B0b immutable artifact/evidence join

**The B0a artifact and B0b inspected installer MUST be the identical full byte sequence under the identical independently approved policy.** Define a canonical, bounded **artifact identity** that binds: exact release/version, expected package basename, independently approved expected SHA-256, **full measured byte length**, and immutable policy digest/revision (including signer, trust roots and required B0b effects rules). B0a publishes this identity with its measured full-byte SHA-256 and size plus authenticated snapshot/verification provenance; B0b MUST remeasure its own verified immutable copy of the transferred artifact, rehash every byte, independently check size and policy digest/revision, and compare both stages against the independently reviewed expected digest **and each other**. A mere matching filename, claimed artifact ID, shared self-declared hash string or two signatures over *different bytes* is insufficient.

Transfer between isolated verification environments must use an independently controlled, integrity-verified immutable/content-addressed handoff with recorded custody (sender/receiver, original sealed evidence identifier, transfer digest/length and trust-policy version). B0b must establish equivalent enforced immutability for its own inspection input before CMS, notarization or payload parsing; macOS read-only mode, original FD, stable timestamps and post-hoc rehash alone are **not** a writer-exclusion proof. If such a handoff or immutable inspection view cannot be demonstrated, **REFUSE** without substituting a live, mutable pathname. Evidence records must have authenticated source and revision so an attacker cannot swap a B0a/B0b report or replay an old approval.

**No operator source decision until a separate join check** verifies full digest, length, canonical artifact identity, approved policy digest, provenance and signatures of **both** records, with verified B0b package-effects disposition. Reject same-name/same-size different-byte packages, different policy revisions, B0a/B0b snapshot mismatch, missing evidence, altered transfer and replay. Report `B0_UNVERIFIED` on any mismatch; never elevate from either stage alone.

## Proposed execution slices (each separately authorized)

Separating three private helpers avoids a monolithic verifier, but does not add another public tool or widen trust/host authority. Review and approve these exact paths **before writing source code**, independently of the exact synthetic T5 trust policy decision:
- `ops/live-e2e/gate_b0_source_verification.py` — **only operator-facing** fixed `verify-synthetic` CLI entrypoint; no real artifact, download, installer or Mac runner.
- `ops/live-e2e/gate_b0_immutable_bytes.py` — private bounded exclusive-writer witness, sealed `memfd` original-byte hashing/length and FD cleanup.
- `ops/live-e2e/gate_b0_sigstore_adapter.py` — private strictly pinned offline external Sigstore verifier handoff and refusal handling only.
- `ops/live-e2e/gate_b0_evidence.py` — private bounded canonical JSON and **non-authorizing** evidence/refusal statuses only.
- `tests/ops/test_gate_b0_source_verification.py` — genuine synthetic test-key signature GREEN and hostile RED tests; never a mock-positive substitute.
- `tests/ops/fixtures/b0a_synthetic/**` — tiny independently authenticated *test-key-only* fixture/bundle/policy records after separate T5 authorization; no real Python.org artifact, secret or unapproved root.
- `ops/live-e2e/README.md` — operator example and offline limitations; documentation only.
- `docs/evidence/2026-10-15-adr19-gate-b0-source-verification.md`, `docs/development-plan.md`, `docs/development-methodology.md` — independently measured **synthetic-only** evidence, accurate UNVERIFIED state and PR workflow.
- `docs/superpowers/specs/2026-10-15-adr19-b0a-offline-source-evidence-cli-design.md` and `docs/superpowers/plans/2026-10-15-adr19-b0a-offline-source-evidence-cli.md` — exact feature spec/plan reviewed in this same Draft PR; this governing plan's changes are limited to the explicit allowlist amendment.
- **Still prohibited:** `.github/workflows/**`, any other native guest/provider/privileged host files, `src/**`, installed interpreter paths, GitHub secrets/permissions, Gate A or UID502 preflight, real package/bundle/verifier/root retrieval, production source authority, host mutation, external networking or Linux Slice C. Allowlist approval does not approve external execution or source trust.

**Task 1 — input/type/budget boundary (RED→GREEN):** define exact immutable release policy, bounded artifact input and **verified exclusive-writer-control at ingestion**; neither read-only open nor a file descriptor alone excludes concurrent writers. Refuse any writer-access ambiguity, oversized or altered source, forged/duplicate fields, symlinks and mismatched identity labels **before any evidence promotion**. Test missing bytes, malicious objects and concurrent writes against the same source inode followed by restoration of bytes/size/mtime: the race case MUST REFUSE even if metadata appears unchanged. A test-only writer-exclusion witness is not a production trust root. RED on missing module, GREEN on minimal refusal path. No signed output yet.

**Task 2 — sealed immutable snapshot, measured original-byte SHA and separately selected verifier handoff (RED→GREEN):** Only under independently demonstrated source writer exclusion, copy the bounded artifact into a private anonymous sealed `memfd` (or independently reviewed equivalent enforced immutable representation), apply/read back write/grow/shrink/seal protections **before** digesting, and record its exact kernel-object identity. Hash **every** sealed byte and record its exact length; both must match an **independently approved** immutable expected artifact policy, not values read from the artifact/bundle. The selected handoff mode is a **separately reviewed policy field**, never an untrusted runtime flag. **Default/direct-FD:** pass that very sealed descriptor to the independently pinned verifier using authenticated inheritance (e.g. `pass_fds`) and prove it does not reopen a mutable package pathname. **Digest-bound candidate (not selectable before this separate plan amendment is approved and merged, and not selectable without a second independent exact tool/signer/root/mode policy approval):** the independently trusted hasher must obtain the digest solely from those sealed bytes, preserve authenticated hash/length/sealed-object identity, and directly hand exactly `sha256:<lowercase-64-hex>` to a pinned verifier API that cryptographically checks that value **against the signed bundle content**. The verifier does **not** remeasure bytes; the authenticated non-circular measured-byte → digest → signed-message chain substitutes for the direct-FD verifier input only under the separately approved mode. No caller-supplied digest, printed `verified=true`, second writable package copy or unapproved signature/tool adaptation counts. Fail to establish writer exclusion, seals, full-byte hash, controlled digest transfer, exact mode or signed-digest binding => `B0A_REFUSED`. RED fixtures: original same-inode mutation then restore matching size/mtime, writable alias, seal failure, post-seal mutation attempt, incomplete capture, wrong measured length/hash, substituted FD, path reopen, changed `sha256:` command argument, same-name/different bytes. GREEN requires demonstrable intact input→verified signature binding, **only synthetic non-authorizing results** before separate artifact approval.

**Task 3 — exact-tool offline Sigstore proof under pinned policy (RED→GREEN):** Before choosing either handoff mode, independently pin and approve the **actual artifact-specific** signer identity and OIDC issuer, Fulcio/Rekor/log identifiers, verifier binary/loader/dependency hashes and exact version, authenticated trust-config/TUF provenance, signature algorithm and bundle semantics, transparency inclusion and signed-time witness, cert valid-time, trusted clock/skew bounds, revocation policy, offline trust-root freshness cutoff and failure behavior. Network disabled; no ambient `PATH` resolution, auto-online refresh, bundle-provided anchors, insecure flag, stale default cache or unauthenticated process/CLI output. **Digest-bound mode** additionally requires demonstration that the **exact pinned verifier** accepts `sha256:<digest-computed-from-sealed-bytes>` plus a supplied untrusted bundle and enforces pinned signer/issuer/root/log/time when binding signed content to that value. **Mandatory synthetic GREEN:** independently create a tiny immutable/sealed test-key fixture under proven writer exclusion, independently measure full SHA+length, and verify a known bundle signing that exact measured digest using the **real selected pinned CLI/version** with expected *test* signer/OIDC, explicitly trusted synthetic roots and valid log/time evidence. Status must be `SYNTHETIC_ONLY` / evidence unapproved: no source authenticity, installer approval or UID502 authority. **Paired RED:** change to a different *same-length* sealed fixture/digest while keeping the original signed bundle; the same verifier must refuse digest↔signature mismatch. An always-refusing adapter **fails** the GREEN requirement. Additional RED: wrong signer/issuer, valid crypto under wrong key, stale/untrusted/expired roots, wrong executable digest, expired certificate, missing signed-time/log witness, revocation/time ambiguity, bundle or policy substitution, malformed/truncated output, crash/timeout and forged CLI success. Actual official package remains `B0_UNVERIFIED` until separately authorized verification.

**Task 4 — handoff-mode audit/status, custody join and focused regression:** Produce deterministic **bounded and authenticated** evidence linking: exact candidate release/name, full sealed-object SHA-256 and measured byte length, independently approved expected artifact SHA/length, verified writer isolation and seal identity, **separately approved handoff mode**, hasher and verifier binary/version/root digests, immutable policy digest/revision, bundle signer/OIDC, transparency inclusion/signed-time/freshness/revocation proofs, bounded authenticated process exit and parsed result, custody provenance and refusal reason. Refuse missing/contradictory/over-budget values, stale decision replay or a verifier/handoff policy not yet independently approved. A successful B0a remains `B0A_EVIDENCE_COLLECTED_UNAPPROVED`; synthetic fixture success is `SYNTHETIC_ONLY`; any uncertainty => `B0A_REFUSED`. **Never** emit `SOURCE_VERIFIED`, `HOST_PROVENANCE_VERIFIED` or an approval boolean from cryptographic output. B0b independently receives an enforced-immutable verified copy, **remeasures all its bytes** and compares **full SHA-256, exact length, release/artifact identity and approved policy digest/revision**, plus authenticated B0a→B0b immutable transfer/receipts; B0b separately verifies Apple Installer CMS, notarization/time/revocation and every script/BOM/payload effect without executing or installing. Required RED tests: same name/length with changed bytes, changed or unauthorized mode/policy, swapped B0a/B0b record, invalid custody, different B0b bytes or policy revision, rollback/replay and fake verifier success; these fail `B0_UNVERIFIED`. Validate targeted hostile/synthetic positive+negative tests, full hosted CI in both supported Python versions, lint/format/types/build, doc links, changed-path allowlist, exact-HEAD CI, and independent security review **only after separate implementation authorization**. A docs-only amendment is validated by static checks and hosted CI; it does not run B0 or Mac tests. No installer/package bytes or secrets in public evidence. Merge any implementation PR only after its own operator decision.

**B0a exit condition (only after separate implementation authorization and exact mode/tool/trust-policy approval):** executable verification logic tested on small *non-official* fixtures, and, **only after separate artifact-use authorization**, the **sealed original-byte snapshot** independently hashed and Sigstore-verified under approved roots with full size, approved policy digest and artifact ID recorded; evidence retained as **B0a-only/unapproved**. Either missing proof or byte-identity ambiguity → `B0A_REFUSED` / `B0_UNVERIFIED`; this is never `HOST_PROVENANCE_VERIFIED` or automatic UID502 approval. No future B0b report may be accepted without an independent cross-stage join of the **same bytes, length and policy**.

### Slice B0b — Apple Installer signature, effects inventory and operator source decision (**separate plan/PR**)

Before any actual package handling, separately review an isolated inspection-host execution plan and **approved immutable artifact-transfer mechanism**. On an independently trusted macOS environment, establish an enforced immutable inspection view of the transferred exact package bytes (not merely an open FD or read-only file mode), independently rehash **all bytes**, measure length and compare the resulting SHA-256, length, canonical artifact ID and policy digest/revision to both B0a's authenticated evidence and the independently approved expected identity **before** CMS, notarization or payload processing. If the Mac inspection host cannot prove exclusive writer exclusion and complete identical bytes through all operations, `B0_UNVERIFIED` is mandatory. Authenticate the **Installer** signature/Apple Developer ID chain and notarization under approved time/revocation policy; enumerate all nested packages, BOM/payload paths, symlinks, pre/postinstall scripts, installer choices, global/system changes and dependencies without running scripts or installing. Reject incomplete inventories and unallowlisted writes, network or executable side effects. Record immutable input/custody and complete package-effects provenance. A **separate source-decision join** must authenticate B0a and B0b evidence, require byte-for-byte identity via full hashes plus length, identical operator-approved policy and approved effects. Mandatory negatives: same filename/size but changed package, stale B0b policy, tampered transfer, switched certificate/identity or replayed B0a evidence. A failure in any stage or join remains `B0_UNVERIFIED`; an operator may decide source suitability only after independently approving the joined evidence, not from either stage separately.

**Stop here.** B1 install-root/provisioning, B2 native FD/APFS/Mach-O/dyld attestation, B3 original-code UID502/APFS nine-row acceptance and B4 protected staging/release each require their own independently reviewed operator gate. Do not equate a clean old native Level-3 run or synthetic Gate A with any of them. [Issue #256](https://github.com/zhangyuz/ssh-over-mcp/issues/256) Linux Slice C remains deferred until operator-confirmed macOS full-feature launch and separately approved portable B2.

## Plan-review questions / approval checklist

- [ ] Confirm B0a's trust policy from an **independent channel** and identify its approving operator; no source identity accepted merely because a bundle or webpage says so.
- [ ] Resolve Sigstore **exact** artifact-specific identity, trusted root/update/expiry, transparency/time and offline revocation policy; select/pin independently trusted verification tool.
- [ ] Confirm verified exclusive writer exclusion at ingestion and independently enforce/read back write/grow/shrink/seal properties **before** measuring all bytes. Explicitly and separately approve one exact handoff mode plus its pinned binary/root/signer policy: **direct-FD** requires same sealed descriptor across authenticated verifier process boundary; **digest-bound** (not available until this amendment is independently reviewed, operator-approved and merged) requires authenticated **locally measured** sealed-byte SHA+length → `sha256:<digest>` → independently pinned verifier's cryptographic signed-bundle binding, never a caller-supplied or bundle-supplied digest. Prove real pinned CLI/version **synthetic GREEN** test-key signature, signer/OIDC/root/log/time check with `SYNTHETIC_ONLY` outcome and paired different-digest **RED** refusal; an always-refusing adapter cannot pass. No selected mode, ambiguous writer/seal/bytes, stale roots/revocation, verifier incompatibility, signature mismatch or mutable pathname fallback => `B0A_REFUSED`.
- [ ] Demonstrate independent B0b remeasurement of **the same full SHA-256 + exact size + release identity + approved policy digest/revision**, immutable transfer and inspection input, authenticated custody/evidence join, and mismatched same-name/same-size package and different-policy/replay negative tests. Failure = `B0_UNVERIFIED`.
- [ ] Confirm Apple package validation **cannot be replaced** by Sigstore or checksum; B0b isolated host, package effects and decision remain separately gated.
- [ ] Review bounded parser/time/resource abuse, evidence provenance, retry/replay and refusal semantics.
- [ ] Record **distinct approval events** for (1) this plan-interface amendment, (2) exact digest/direct-FD handoff-mode + artifact-specific signer/tool/root/offline freshness/revocation policy, (3) future synthetic-only B0a implementation, (4) real package/bundle retrieval and use, (5) B0b independent isolated Mac inspection and Apple Installer effects, and later (6) B1 provisioning, B2 at-use attestation, B3 original UID502/APFS nine-case and B4 staging/release. Merging a docs-only plan amendment authorizes **none** of (2)–(6); no CI dispatch, provider or host action follows automatically.
