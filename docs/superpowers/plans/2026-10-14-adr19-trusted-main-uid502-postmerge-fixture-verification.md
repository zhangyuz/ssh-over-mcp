## UID502 fixture-matrix state machine and terminal acceptance

**One invocation, many independently owned case wrappers.** The verification-only parent must be empty at the start of a **new workflow invocation**. Within that single invocation, initialize a strict case manifest (fixed test case identifiers, one 32-hex nonce per case, expected run-root dev/inode/uid/gid/mode/ACL and all pinned entry names); validate its exact full inventory before each case. Run all success cases first, each with its own pre-dispose escrow and complete exact-entry cleanup. Then execute the deliberately adversarial failure cases, each in a fresh wrapper, **without rerunning any original one-shot disposer after a failure**. Already-retained failures from *this same invocation* may be observed only when their complete original manifest is unchanged; an old/future invocation cannot adopt them and must refuse on preflight.

| --- | --- | --- |
| Clean preflight → positive cases | `IN_PROGRESS_CLEAN` | No prior verification-only residual; trusted SHA/UID/interpreter, provider/QEMU and both legacy observations clean; harness-owned escrow acquired before each original 2A success disposal |
| Expected negative case refusal | `EXPECTED_REFUSAL_RETAINED` for **that case only** | Original merged function and exact injected fault point observed; expected `NamespaceError`/failure and `cleanup_uncertain` flags asserted; outside target unchanged; complete **case-specific** original identity/inventory retained and logged. ## Independent FD escrow ownership — required positive-case protocol

The **2A module owns its own** workspace, staging/ancestor and permit claim/Library FDs and intentionally closes them on a successful `_dispose_never_started_fixture()`. **The harness must separately own independent original witnesses obtained *before* calling the disposer**, including its originally opened nested Library/wrapper ancestor descriptors and a verified `F_DUPFD_CLOEXEC` (or checked `dup`+CLOEXEC) of the original claim file FD. This is an independent harness escrow derived from the original exclusively claimed object, **not a later absolute-path reopen**, not a new marker claim, and not an automatic retry/deletion of a failed fixture. Snapshot and verify each exact parent/name/child FD edge (dev/inode/uid/gid/full mode/ACL, `st_nlink==1` for marker) before transfer; scan directories through independent `open('.', dir_fd=...) ` descriptions, not a cursor-sharing `dup` scan.

A positive case may invoke original 2A disposal **only after escrow acquisition and verification succeed**. The disposer closes its **own** FDs; the harness validates this fact using the returned workspace/permit closed state and controlled original close-call audit (never assumes a stale integer FD still identifies an object). Independently held escrow survives. Then and only then, after rechecking all exact entries and zero unknown children via escrow, perform narrowly scoped success-only teardown of the *original* test marker and now-empty literal nested wrappers, ending with the originally created nonce wrapper using held parent FDs. No `shutil.rmtree`, pathname fallback, re-claim, generic residual deletion, or second call to the one-shot 2A disposer.

If escrow acquisition, identity validation, unlink, `rmdir`, final empty verification or `close` is uncertain, never resume deletion or retry; classify UNVERIFIED with retained evidence. Every escrow FD has **one owner and one close attempt**, including failed intermediary opens and exceptions. `test_escrow_retains_original_witness_after_2a_dispose` RED→GREEN must verify original 2A handles are fully closed on success, independent escrow remains usable and original-identity-bound, and only exact successful marker/empty-wrapper entries are removed. `test_escrow_acquisition_or_close_failure_never_retries_cleanup` rejects leaked/double-closed escrow FDs and any delete on failed escrow acquisition. Negative expected-refusal cases **never enter success-only teardown**; close escrow descriptors without filesystem mutation and retain forensic inventory.
